# Three Specific Leads: Real Shack-Hartmann Spot Image Datasets

## Lead A: Ramirez-Quintero et al. 2025, Scientific Reports (s41598-024-80615-8)

### Takeaway
This is a real, physically-recorded optical-bench experiment (custom monocular visual simulator with a real Hartmann-Shack sensor and a real SLM), but **no raw-image dataset is publicly downloadable**: the Data Availability statement explicitly restricts access to "upon reasonable request." Aberration ground truth is **commanded via SLM phase-map setpoints, not independently/interferometrically measured**, which is a critical caveat for using this as verified ground truth. Native camera resolution is 1280×1024 px; the paper's stated NN input size and exact preprocessing pipeline to reach it were not found in the extractable text (numbers appear to be embedded in figures/tables not captured by automated extraction) — this is a **gap**, not a confirmed absence.

### Cited Findings
- Direct fetch of the Nature.com article page (`https://www.nature.com/articles/s41598-024-80615-8`) was blocked: the server issued an HTTP 303 redirect to Nature's `idp.nature.com` login/authorization endpoint for both the HTML and `.pdf` variants, preventing automated retrieval of the primary source page. — [Source](https://www.nature.com/articles/s41598-024-80615-8)
- A free full-text mirror was located and successfully read on PubMed Central: PMC11926174. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- **Data Availability statement, quoted verbatim from the PMC full text**: "Data underlying the results presented in this paper are available from the authors upon reasonable request." This is a request-only policy — there is **no Figshare/Zenodo/GitHub/Supplementary-Information download link** for the raw images. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- Sensor/optics specs extracted from the Methods text via PMC: CMOS camera resolution **1280×1024 pixels**, pixel size **5.3 μm**, microlens (lenslet) pitch **300 μm**, lenslet focal length **3.2 mm**, lenslet array from **Flexible OKO Optical (Rijswijk, The Netherlands)**. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- The spatial light modulator used to generate the commanded aberrations is a **Pluto LCoS (PLUTO-NIR), Holoeye Photonics AG, Berlin**, 1920×1080 px resolution, 8 μm pixel pitch, max phase modulation 2π at the working wavelength. Confirmed independently by Holoeye's own reference/citation page for this exact paper, which lists "PLUTO / PLUTO-2 Spatial Light Modulators" as the product used. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/); [Source](https://holoeye.com/papers-references/experimental-wavefront-sensing-techniques-based-on-deep-learning-models-using-a-hartmann-shack-sensor-for-visual-optics-applications/)
- Aberrations were generated by the SLM projecting "phase maps of selected Zernike coefficient combinations," with coefficients "selected uniformly at random" — i.e., the labels are the **commanded SLM setpoints**, not an independent/interferometric measurement of the actual wavefront delivered. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- The experimental setup is a real optical bench: "A monocular visual simulator equipped with active optics was designed and built by the Optics and Photonics group at the University of Antioquia," containing a laser, a diameter pupil, an SLM, a Hartmann-Shack wavefront sensor, and an artificial eye — confirming the data is physically recorded, not simulated/rendered. — [Source](https://www.researchgate.net/publication/... via search snippet citing the same setup) (secondary aggregator; corroborated by PMC methods text describing the same camera/SLM hardware) — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- The paper generated two dataset types: a Noise-Free Images (NFI) dataset and an Artificial-Eye Images (AEI) dataset, each split into training/validation/test subsets. The exact image counts and split sizes were rendered as embedded numerals/graphics in the source and could not be extracted by automated text tooling. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- No explicit mention of "256" (e.g. 256×256) was found anywhere in the extractable full text, nor were explicit statements of a crop/resize/downsample/ROI/normalization pipeline. The paper states images were processed through a modified ResNet but does not spell out the preprocessing steps in the extractable text. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- No statement was found (in the extractable text) about whether multiple repeated exposures were captured per aberration setting; the text only specifies that Zernike coefficients were "selected uniformly at random," implying each sampled aberration setting maps to one capture, but this was not stated explicitly either way. — [Source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11926174/)
- Authors: Juan Sebastián Ramírez-Quintero, Andrés Osorno-Quiroz, Walter Torres-Sepúlveda, Alejandro Mira-Agudelo (Optics and Photonics group / Grupo de Óptica y Fotónica, Universidad de Antioquia, Colombia). Published in Scientific Reports 15, article 9652 (2025), DOI 10.1038/s41598-024-80615-8, listed as Open Access. — [Source](https://pubmed.ncbi.nlm.nih.gov/40113787/); [Source](https://holoeye.com/papers-references/experimental-wavefront-sensing-techniques-based-on-deep-learning-models-using-a-hartmann-shack-sensor-for-visual-optics-applications/)

### Inferences
- Because the Data Availability statement is a "request on reasonable request" clause rather than a repository DOI/link, this dataset should be classified as **request-only**, not publicly downloadable, for the purposes of the survey.
- Because ground truth is the SLM-commanded phase map (not an interferometric or independent re-measurement of the delivered wavefront), any reconstruction-accuracy numbers in the paper are accuracy-against-setpoint, not accuracy-against-true-delivered-wavefront. SLM phase nonlinearity/calibration error, diffraction efficiency, and residual aberrations in the relay optics would not be captured by this ground truth.
- No bit depth of the camera was stated in the extractable text — likely omitted or in a table/figure not extracted; flagged as a gap below.

### Gaps
- Could not directly load the canonical Nature.com article/Supplementary Information PDF (redirected to a login wall by automated fetch); relied on the PMC mirror, which is the accepted-manuscript/typeset full text and should be equivalent in content, but the Supplementary Information file itself (which might contain additional dataset/preprocessing detail or a link) was not separately inspected.
- Could not confirm the specific "256×256" neural-network input size mentioned in the task's own framing — it was not found in the extractable text. It's unclear whether this number is stated in the paper's figures/tables (which the automated extraction could not read) or is not accurate / comes from a different source. This should be treated as **unconfirmed**.
- Camera bit depth (8-bit vs 10/12-bit) was not found in the extractable text.
- Whether repeated exposures per aberration setting were captured (needed to separate sensor noise from systematic/model error) is unconfirmed either way.
- Whether flat-wavefront reference frames, dark frames, a lenslet map, or a pupil mask are included/described anywhere (even in the request-only dataset) is unconfirmed — no mention was found in the accessible Methods text, and since the data itself isn't downloadable, this can't be directly checked.
- License/reuse terms for the (request-only) dataset itself are not stated beyond the journal article being Open Access (which covers the text/figures under the Nature/Springer Open Access license, not necessarily the underlying image data).

## Lead B: Durham University "PPPPP" laboratory collection (collections.durham.ac.uk/collections/r2gb19f5844)

### Takeaway
This collection is **not** a Shack-Hartmann lenslet-spot-image dataset in the sense the survey is looking for. Its own title is **"PPPP beam profiles and measured Shack Hartmann slopes from the PPPPP experiment"** — i.e., the raw camera images in the collection are from the **PPPP (Projected Pupil-Plane Pattern) sensor**, a lenslet-free pupil-imaging wavefront-sensing technique distinct from Shack-Hartmann, while the Shack-Hartmann component is present only as **already-computed slopes** (a derived quantity), not raw lenslet spot-pattern images. Data was physically recorded on a real adaptive-optics lab bench (DARC real-time-controller-driven cameras + deformable mirror), so it is genuine experimental data — just not raw SH spot images.

### Cited Findings
- Direct WebFetch of the task-given URL (`https://collections.durham.ac.uk/collections/r2gb19f5844?view=list`) and several path/query variants (`?page=1`, `?page=2`, no query string, `/files/r2gb19f5844`) consistently returned **HTTP 404 or 500** to the automated fetch tool — the site appears to require a JS-rendered browser session that the fetch tool could not satisfy. Content below was therefore reconstructed from search-engine-indexed snippets of the same pages plus a directly-fetchable sibling "file" page, not from a full independent page render — flagged as **verified via cached/indexed content, not a direct live browse**. — [Source](https://collections.durham.ac.uk/collections/r2gb19f5844?page=2)
- The collection's exact title, confirmed via search index snippet: **"PPPP beam profiles and measured Shack Hartmann slopes from the PPPPP experiment [dataset]"**. — [Source](https://collections.durham.ac.uk/collections/r2gb19f5844?page=2)
- Collection description (via search index snippet): "a collection of 2D images measured by two cameras, and wavefront sensor slopes from a laboratory experiment called PPPPP, according to the PPPP methodology for wavefront sensing... Associated with the data are aberrations produced by a deformable mirror in the experiment, calculated wavefront error, and data quality quicklook plots." — [Source](https://collections.durham.ac.uk/collections/r2gb19f5844?page=2) (search snippet)
- Experimental rig description (via search index snippet): "The experiment PPPPP had three cameras, identically controlled via three instances of the DARC RTC, and one DM (deformable mirror), controlled via a separate computer that interpreted commands sent remotely from an automated script written in Python 2.7." DARC = Durham Adaptive optics Real-time Controller, Durham's own real-time control software for AO systems. — Inference based on the above cited snippet.
- A directly-fetchable sibling record for a related/parent DOI was successfully read in full: `https://researchdata.durham.ac.uk/files/r2np193923h`, titled **"README documentation for PPPP beam profiles and measured Shack Hartmann slopes from the PPPPP experiment"** (i.e., a README file describing this same dataset). Metadata: License **Creative Commons Attribution-ShareAlike 4.0 International (CC BY-SA 4.0)**; Creator **Nazim Bharmal** (Durham University); Deposited **5 December 2023**; DOI **10.15128/r2np193923h**; Funder: **Science and Technology Facilities Council (STFC)**; file size 9,165 bytes (plain text/Markdown). — [Source](https://researchdata.durham.ac.uk/files/r2np193923h) (direct fetch)
- This DOI (`10.15128/r2np193923h`) is the exact data-repository link cited by the associated peer-reviewed paper, "Laboratory demonstration of single-camera PPPP wavefront sensing using neural networks," International Journal of Optomechatronics, Vol 18, No 1 (2024), DOI 10.1080/15599612.2024.2386985, whose search-index summary states: "Data from the PPPP cameras (1 and 2), WFS, and supporting material are available online from the Durham University research data repository, http://doi.org/10.15128/r2np193923h." — [Source](https://www.tandfonline.com/doi/abs/10.1080/15599612.2024.2386985) (search snippet; direct fetch of the Tandfonline abstract page returned HTTP 403 to the automated tool)
- The same paper's search-index summary explains the PPPP technique itself: "The Projected Pupil Plane Pattern (PPPP) offers an alternative solution [to laser guide star AO] by projecting a collimated laser beam across the telescope's entire pupil," using "two beam profiles obtained simultaneously from two different distances from the telescope pupil" to resolve a gain/distance degeneracy — confirming PPPP is a **lenslet-free, pupil-plane beam-imaging** WFS technique, structurally different from a Shack-Hartmann lenslet array. — [Source](https://www.tandfonline.com/doi/abs/10.1080/15599612.2024.2386985) (search snippet)
- No pixel/bit-depth/resolution specs for the PPPP or SH cameras were found in any accessible snippet or page; a lenslet map/pupil mask/flat-reference/dark-frame inventory for this specific collection could not be confirmed since the page itself could not be live-browsed.

### Inferences
- Given the collection's own title explicitly separates "PPPP beam profiles" (images) from "measured Shack Hartmann slopes" (a derived, already-reduced quantity), it is very unlikely this collection contains raw SH lenslet spot-pattern frames — the SH sensor's raw camera output appears to have been reduced to centroid slopes before deposit, if it was captured at all as a separate item.
- The r2np193923h "README" file being reachable while the top-level r2gb19f5844 collection page 404s under automated fetch suggests the Durham repository's collection-index pages are JavaScript-rendered (client-side app), while individual file/object pages resolve to a server-rendered fallback that the fetch tool can retrieve. A human/browser session would very likely be able to browse the full item list where automated fetch could not.
- The CC BY-SA 4.0 license and STFC funder line indicate this is a fully public, reuse-permitted dataset (not request-only) — access itself does not appear to be gated, only the automated tooling's ability to render the page.

### Gaps
- **Could not obtain a full, authoritative file-by-file listing (file names, formats, sizes, counts) of the r2gb19f5844 collection.** All content above about the collection's title/description/keywords/creation date came from search-engine cache snippets, not from directly parsing the live collection page — the page returned 404/500 to the fetch tool on every attempted variant (`?view=list`, `?page=1`, `?page=2`, no query, `/files/` path). This should be treated as **unconfirmed by direct render**, though corroborated by two independent search-index snippets and one directly-fetched sibling README-file page describing the same dataset by the same title.
- Could not confirm whether the deposited PPPP camera images are raw (unprocessed sensor frames) versus already dark-subtracted/normalized "beam profile" images — the word "beam profiles" suggests some minimal processing (e.g., background subtraction) may already have been applied before deposit, but this is not confirmed.
- Could not confirm total file count or total dataset size for r2gb19f5844.
- Could not confirm whether repeated exposures were taken per aberration/DM setting (the description mentions "aberrations produced by a deformable mirror" and "calculated wavefront error" and "quicklook plots," implying many DM settings were exercised, but repeat-exposure structure is unconfirmed).
- Could not confirm presence/absence of dark frames, flat/reference frames, a lenslet map, or a pupil mask as explicit named files in the collection.
- The relationship between the two DOIs is inferred (r2np193923h's README file describing the same dataset title as the r2gb19f5844 collection page) rather than directly observed as a single navigable page; a person with working browser access to `https://collections.durham.ac.uk/collections/r2gb19f5844` should verify directly.

## Lead C: Zenodo record 14964320

### Takeaway
This Zenodo record is **verified directly**: it is a code-and-numerical-data repository ("Codebase for Wavefront Aberration Calibration Using Supervised and Deep Learning (SHWFS)"), not a raw camera-image dataset. There is **no evidence of real camera-recorded images** anywhere in the record — the files are Jupyter notebooks, Python scripts, CSV/XLSX statistics summaries, and large binary `.dat` arrays (most plausibly simulated Zernike-coefficient/wavefront training tensors, consistent with a "calibration using supervised/deep learning" codebase), with no image file formats (no .png/.tif/.fits/.raw) present at all.

### Cited Findings
- Directly fetched both the human-readable Zenodo record page and the Zenodo REST API JSON for this record. — [Source](https://zenodo.org/records/14964320); [Source](https://zenodo.org/api/records/14964320)
- Full title: **"Codebase for Wavefront Aberration Calibration Using Supervised and Deep Learning (SHWFS)."** Creator: **Jara, Mario Alberto**. DOI: **10.5281/zenodo.14964320**. Publication date: **February 2025**. License: **Creative Commons Attribution 4.0 International (CC BY 4.0)**. — [Source](https://zenodo.org/records/14964320); [Source](https://zenodo.org/api/records/14964320)
- Description (paraphrased from the record): the repository explores "innovative methodologies to calibrate wavefront aberrations by leveraging machine learning techniques," emphasizing supervised and deep learning approaches for Shack-Hartmann wavefront sensors — i.e., it is framed as a computational/methods codebase, not a sensor-data release. — [Source](https://zenodo.org/records/14964320)
- Complete file listing obtained (25 files, ~35.9 GB total declared size), with formats limited to: Jupyter Notebooks (`.ipynb` — e.g. `3.4.2_BayesianOptimization_GradientDescent.ipynb`, `DynamicHypernetwork_Results.ipynb`, `GradientDescent_Results_TestSet.ipynb`, `LSQ_Results_TestSet.ipynb`), Python scripts (`Statistical_Aberrations.py`, `Shack-Hartmann Limit.py`), spreadsheet/CSV summary files (`original_data.xlsx`, `Base_Statistical_Summary_X.csv`, `Base_Statistical_Summary_Y.csv`, `Base_summary_statistics_magnitude.csv`, `Statistics_samples_x_y.csv`, `Total_summary_statistics_magnitude.csv`, `Total_summary_statistics_x.csv`, `Total_summary_statistics_y.csv`), and large generic binary data files named `W_train.dat` (24.5 MB), `W_test.dat` (4.1 MB), `W_single_sample.dat` (8.2 KB), `Z_train.dat` (777.7 MB), `Z_test.dat` (129.6 MB), `Z_single_sample.dat` (259.1 KB). No image-format files (png/jpg/tif/fits/raw) appear anywhere in the listing. — [Source](https://zenodo.org/api/records/14964320) (API JSON file manifest, cross-checked against the human-readable record page)
- Exact file sizes and MD5 checksums for at least 10 of the 25 files were captured directly from the API JSON, e.g. `Z_train.dat` = 777,674,238 bytes (MD5 7a5ba1ea3a36d4e70eb76454508e7972), `Z_test.dat` = 129,609,689 bytes, `W_train.dat` = 24,505,911 bytes, `original_data.xlsx` = 21,747 bytes. — [Source](https://zenodo.org/api/records/14964320)
- The file naming convention ("W_" and "Z_" train/test/single_sample .dat files, alongside notebooks named for "Bayesian Optimization," "Gradient Descent," and "Dynamic Hypernetwork" results) is consistent with W = wavefront/Zernike-weight vectors and Z = some other tensor (possibly Zernike-mode or z-position/measurement arrays) used to train regression/deep-learning calibration models — i.e., **numerical training data, not imagery**. This is an inference from naming pattern, not a direct statement in the record's metadata.

### Inferences
- Given (a) the record's own framing as a "codebase," (b) the complete absence of any image file format in the 25-file manifest, and (c) the presence of statistics/summary files and Jupyter notebooks focused on optimization/regression results, this record should be classified as **code + derived/synthetic numerical data, with no raw camera images at all** — consistent with the task's suspicion, and directly confirmed by file-listing inspection rather than by title/abstract alone.
- The CC BY 4.0 license means whatever is here (code and .dat arrays) is fully open and reusable, but that access does not extend to any raw SH camera images because none exist in this record.

### Gaps
- The exact internal structure/format of the `.dat` files (e.g., whether they are NumPy arrays, raw floats, or something else) was not opened/parsed — per task constraints, only metadata/listings were inspected, not file contents. It remains formally unconfirmed (though highly likely given file naming and description) that these `.dat` files contain synthetic/simulated wavefront data rather than, say, some other numerical encoding of real measurements; either way, they are not images.
- No linked GitHub repository or associated publication/preprint was found or checked for this Zenodo record in this pass — if one exists, it might state whether the underlying "supervised and deep learning" training data (the W_/Z_ .dat files) was generated from simulation or from a real optical bench feeding a SHWFS; this remains unconfirmed from the Zenodo record alone.
